# 터미널 목록의 세션별 정보 (2026-09-16)

`fix/terminal-list-session-context`는 `custom`의 `3c36d454f2`에서 시작했다.

- **Codex 작업 폴더**: 기존 파서는 Claude의 최상위 `cwd`만 읽었다. Codex의
  `session_meta.payload.cwd`, `turn_context.payload.cwd`, 도구 호출의 `workdir`도 읽는다.
  전사 경로가 없는 훅은 세션 ID로 기존 세션 파일 탐색기를 사용한다.
- **PR 누락**: Claude의 `tool_use`/`tool_result`뿐 아니라 Codex의 호출/결과를
  `call_id`로 연결한다. 생성 명령이 백그라운드로 넘어가면 잡 ID를 기억해 후속 조회를 연결한다.
  단순 조회·대화에 나온 링크는 계속 제외하며 GitLab MR도 같은 규칙을 쓴다.
- **읽기 경계**: 최초 전사는 처음부터 순차적으로 읽고 이후에는 추가된 완성 레코드만 읽는다.
  생성 호출의 기억을 유지하므로 예전 4MB 꼬리 제한과 256KB 겹침 구간 밖의 결과도 찾는다.
  미완성 UTF-8 레코드는 다음 읽기로 미루고 파일 교체·축소 시 캐시를 초기화한다.
  전사가 있으면 그 세션의 PR을 사용해 같은 셸의 이전 세션 기록이 섞이지 않게 한다.
- **일반 셸 숨김**: 페인별 훅·전경 프로세스·제목으로 에이전트 존재를 판단한다.
  `done`은 턴 완료이므로 입력 대기 중인 에이전트는 남긴다. 셸 복귀 증거가 있으면 숨긴다.
  숨긴 뒤에도 `탭.페인` 번호는 원래 위치를 유지한다.
- **Codex 제목 복제**: 훅 처리에서 페인 제목이 없으면 탭 제목이 상태에 복사될 수 있었다.
  Codex 목록 이름은 사용자 지정 페인 제목 → 자기 프롬프트 → 자기 페인의 실시간 제목 →
  세션 ID 순으로 고른다. 다른 페인이 정한 탭 제목과 상태에 복사된 제목은 쓰지 않는다.
- **갱신**: 컨텍스트를 10초마다 읽되 중첩 요청은 막는다. 세션이 바뀌면 이전 컨텍스트를
  즉시 숨기고 늦게 도착한 이전 요청의 결과를 무시한다.

WSL 파일 읽기는 기존 격리된 전사 파일 접근 경로를 사용한다. SSH 전사 컨텍스트 조회는
기존부터 로컬 전용이었으며 이번에도 원격 조회를 추가하지 않았다. 대신 연결 ID가 있는 요청은
로컬 파일·세션 탐색으로 보내지 않아 동명 경로가 다른 호스트의 정보로 오인되지 않게 한다.
원격 에이전트 표시는 로컬 전경 프로세스의 부재만으로 지우지 않는다.

회귀 테스트는 Codex/Claude 형식, GitLab, 지연된 생성 결과, 긴 전사, 잘린 UTF-8,
세션 간 분리, 일반 셸 필터와 입력 대기 상태, 제목 중복, 비동기 컨텍스트 교체를 다룬다.
저장소가 지정한 `$electron` 스킬을 로컬에서 찾지 못해 실제 Electron 화면 검증은 미수행이다.

검증: 관련 10개 테스트 파일의 74개 테스트, 전체 타입 검사, 변경 파일 린트·포맷 검사,
max-lines 검사, Windows 패키징을 통과했다. 실행 중인 앱은 교체하지 않았고 검증용 빌드는
`dist-terminal-context/win-unpacked/Orca.exe`에 만들었다.

## 추가 수정 및 custom 반영

- 유휴 탭은 저장된 이전 작업명 대신 활성 터미널의 현재 이름을 표시한다.
- Codex는 마지막 입력보다 세션 작업 이름을 우선한다. 기존 AI Vault 조회를
  분할 터미널별로 확장하고 세션 ID와 실행 호스트가 바뀐 뒤 도착한 응답은 버린다.
- 이번 반영 전 관련 11개 테스트 파일의 73개 테스트와 메인·렌더러 타입 검사를 통과했다.
- 재시작 후 화면 깨짐은 조사 중이다. 창 크기 변경으로 정상화된다는 제보를 받았으며,
  이번 변경에는 해당 렌더링 문제의 수정이 포함되지 않는다.
